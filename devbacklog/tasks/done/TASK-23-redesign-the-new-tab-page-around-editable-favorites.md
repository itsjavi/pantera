## Goal

A calm New Tab page that's Pantera's own: a clean, soft gradient that stays neutral or follows
the theme, the panther art in a corner, and the user's favorites in the middle, editable, in a
centered grid that grows. Asked for by the user on 2026-10-27, to ship in the same build as
TASK-22.

## Acceptance criteria

- [x] Favorites can be added, edited, removed and reordered on the page
- [x] Favorites start empty; browsing history never fills the grid
- [x] The grid takes up to 48 favorites and 8 columns, adds rows as it grows, and stays centered
- [x] The background is a soft gradient from the theme's colors (neutral in the default theme)
- [x] The panther sits in a corner: generated from the icon's paths, colored from the theme
- [x] Checked in a build in light and dark mode, with no network requests from the page

## Notes

Research (2026-10-27, `build/src`): without Google as the search engine, `chrome://newtab` is
`chrome://new-tab-page-third-party` (`chrome/browser/search/search.cc`), a ~120-line page around
`<cr-most-visited>` (`ui/webui/resources/cr_components/most_visited/`). That component already
edits custom shortcuts (dialogs, drag to reorder, undo) through the shared `MostVisitedHandler`,
stores them in prefs, and loads icons from `chrome://favicon2` (the local favicon cache, no
server fallback). The third-party page gave its editing dialogs empty strings, custom links were
capped at 10 (`components/ntp_tiles/constants.cc`), the grid at 5 columns and 2 rows unless
`reflowOnOverflow` is set, and `MostVisitedSites::ShouldQueryTopSites()` showed history-based
tiles until the first edit, which then kept them. `kNtpUseMostVisitedTiles` defaults to false, so
custom shortcuts are already the default mode.

Changes, in `patches/pantera/ntp/`:

- `edit-favorites.patch`: turns on custom shortcuts (the page enabled only most visited tiles,
  so the first build showed a "Web Store" tile and no Add button) and gives them the full NTP's
  `IDS_NTP_CUSTOM_LINKS_*` strings.
- `favorites-without-history.patch`: `ShouldQueryTopSites()` only queries history when the user
  chose most visited sites, so favorites start (and restore to) an empty list.
- `grow-the-favorites-grid.patch`: 48 custom links on desktop, up to 8 columns.
- `pantera-new-tab-page.patch`: the gradient on a full-window `html::before` layer
  (`linear-gradient(200deg, background 35%, color-mix(background, text 6%))`; on the root
  background, the theme's tiling and position cut it 63 px short of the right edge), the
  panther, `reflowOnOverflow`. Theme images still replace the gradient and hide the panther.

The panther is one CSS mask, `panther.svg`, generated by `scripts/make-icon.swift` into
`branding/overlay/chrome/browser/resources/new_tab_page_third_party/`: the app icon's one-color
panther (DECISION-10) in the theme's text color at 7%, the eye and whiskers cut out. The user
first saw it with an amber eye, found it odd and too prominent in light mode, and chose one
color for the whole panther, then for the app icon too.

Compiled on 2026-10-27: the three C++ files, and the page's TypeScript (its grit build ran tsc).

### Verified (2026-10-27)

In the build, on a test profile: the grid started empty with the Add tile; 12 favorites added
through the page's dialog laid out as 7 + 6 centered, with the "Shortcut added / Undo" toast;
they survived restarts. Light and dark screenshots show the gradient and the panther. The
network log of that session had no requests from the page (favorite icons are local monograms
until a site is visited). It did catch seven search engine favicon requests from elsewhere:
TASK-26.
