## Context

Porting Brave's ad blocking adds roughly 10–15k lines of C++, Rust and TypeScript, plus about
6 MB of Rust crates. Patches that create files would carry all of that, and new code is hard to
read and edit as a diff. Brave keeps its code in `//brave` and hooks it into Chromium. The user
chose the same layout on 2026-10-28.

## Decision

- Source files that Pantera writes or ports live in `pantera/` at the repository root, at the
  paths they have under `//pantera`. `build.sh` copies the folder to `build/src/pantera`.
- Patches in `patches/pantera/` only hook that code into Chromium (a dependency in a `BUILD.gn`,
  a call from a client class) and stay small.
- Rust crates are added to Chromium's own `third_party/rust/chromium_crates_io` with Chromium's
  unmodified gnrt. The new crate folders live in `third_party/rust/` at the repository root, at
  their Chromium paths, and `build.sh` copies them over the source. Changes to Chromium's existing
  files there (`Cargo.toml`, `Cargo.lock`, `gnrt_config.toml`, regenerated `BUILD.gn` files)
  are a patch, so an upstream sync that touches them fails loudly.

## Consequences

- Third-party crates are committed unmodified first, as generated by `gnrt vendor`, and their
  build files in a separate commit.
- Files ported from brave-core keep their MPL-2.0 header and say where they came from
  (DECISION-11).
- When Chromium updates its crates, the crates patch has to be regenerated with gnrt.
