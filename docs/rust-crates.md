# Rust crates

Chromium builds Rust crates with GN from sources vendored in `third_party/rust/`. Pantera adds
Brave's ad-block engine, [adblock-rust](https://github.com/brave/adblock-rust), and the crates it
needs to that set with Chromium's own tool, gnrt (DECISION-13, TASK-31).

| Path | Contents |
|---|---|
| `third_party/rust/<crate>/<epoch>/` | `BUILD.gn` and `README.chromium` generated by gnrt for each new crate |
| `third_party/rust/chromium_crates_io/vendor/<crate>-<epoch>/` | The crates' sources from crates.io |
| `third_party/rust/chromium_crates_io/patches/<crate>-<epoch>/` | gnrt patches applied while vendoring: license files missing from three crates |
| `patches/pantera/rust/add-adblock-crates.patch` | Changes to Chromium's own files: `Cargo.toml`, `Cargo.lock`, `gnrt_config.toml` and the `BUILD.gn` files of crates that gain features |

`build.sh` copies `third_party/` over the source after patching. Never edit generated files by
hand: change `Cargo.toml` or `gnrt_config.toml` and regenerate.

## Regenerating

After a Chromium update the patch stops applying, because Chromium changes its lockfile and crate
files with every release. To add a crate or change features, the steps are the same.

1. Build the new Chromium source with `build.sh` far enough to have `build/src` and
   `build/src/out/Default/gn`, or apply the patch series by hand without the crates patch.
2. Run `scripts/update-rust-crates.sh prepare`. It copies Chromium's crate folders from
   `build/src` into `.local/chromium`, as released, and applies Pantera's crates on top. If the
   patch no longer applies, add `adblock` to `Cargo.toml` again by hand and drop the rejected
   hunks: gnrt regenerates the rest.
3. Edit `.local/chromium/third_party/rust/chromium_crates_io/Cargo.toml` or `gnrt_config.toml`.
4. Run `scripts/update-rust-crates.sh update`. It runs `gnrt vendor` (which downloads from
   crates.io) and `gnrt gen`, then rewrites `third_party/` and the crates patch.
5. Build `pantera_unittests` and commit new crate sources unmodified, separately from the build
   files.

## gnrt config notes

- `gnrt vendor` adds an `allow_unsafe` entry for each new crate. When a crate exists in two
  versions, one entry covers both; split it into `[crate."name@vN"]` entries when the versions
  need different settings (rand_core and thiserror do).
- Crates whose build script only probes the compiler (flatbuffers, thiserror 1) get
  `remove_build_rs = true`.
- selectors' build script generates a source file, declared in `build_script_outputs`.
- regex and siphasher were test-only in Chromium; adblock-rust ships them, so their `group`
  setting is removed. aho-corasick, which regex uses, was never built outside tests either, and
  its config wrongly said it had no unsafe code.
- A crate that reads files with `include_str!` (derive_more-impl reads its docs) needs them in
  `extra_input_roots`; the build fails with "Rust source file or input not in GN inputs" otherwise.
- gnrt refuses crates without a license file. Add one with a patch in
  `chromium_crates_io/patches/<crate>-<epoch>/`, taken from the crate's upstream repository, as
  Chromium does for siphasher.
